# 三人分工与交接

当前只分配三条完整 baseline：每人负责一条完整方案，优先完成前三问；第四问若复杂度过高，可阶段性暂缓。甲/乙/丙为占位称呼，可替换为实际姓名。

## 1. 当前分配：一人一个 baseline

| 人员 | 唯一实施任务 | 范围 | 交付 |
|---|---|---|---|
| 成员甲 | [Baseline A：可解释基线](./baselines/Baseline-A.md) | A 系列；前三问优先，第四问可暂缓 | 一套可复现代码、结果和 baseline 报告 |
| 成员乙 | [Baseline B：机制模型基线](./baselines/Baseline-B.md) | B 系列；前三问优先，第四问可暂缓 | 一套可复现代码、结果和 baseline 报告 |
| 成员丙 | [Baseline C：非线性与前沿对照](./baselines/Baseline-C.md) | C 系列；前三问优先，第四问可暂缓 | 一套可复现代码、结果和 baseline 报告 |

Q1-A 等单问文档只是完整 baseline 的技术步骤，不代表额外分配的独立任务。当前不增加优化方向负责人、研究主线负责人或复杂问题专项负责人。

## 2. 统一执行范围

1. 三人先共同确认指标、单位、数据来源、切分和评价目标，遵循[公共约定](./baselines/00_公共约定与接口.md)。必要的数据清洗属于 baseline 前置工作。
2. 各自先按第一问 → 第二问 → 第三问的顺序完成自己的 baseline；第四问若复杂度过高，可先不实施，并说明待完成范围和原因；复用已有公共产物时记录版本，不必重复清洗。
3. 单问算法横向比较使用同一上游输入；整条路线比较则明确上游不同，不能把最终差异都归因于一个算法。
4. 每人只需提交该 baseline 的基本实现、必需验证、结果和局限。较复杂的模型改进、深入机理论证、扩展约束和研究故事不在当前分配内。
5. 遇到复杂或不可辨识的问题，先报告现象、证据和可运行的简化结果；是否深入研究留待讨论。不得把简化结果冒称已经满足全部题目要求。

已实施问题的题面数据和验证要求仍须满足。第四问若暂缓，其逐任务聚合、桥接、归因和预测可同步暂缓，标明“第四问未完成”，不把前三问阶段性交付描述为完整四问解答。

## 3. 第四问的阶段安排

- 实现难度和时间成本可控时，继续完成本路线第四问的基本版本。
- 若复杂度过高，可以先不做，优先交付前三问的可复现结果。
- 报告中单列第四问状态、已有输入、待完成内容和复杂度原因；何时补做留待讨论。
- 暂缓第四问不会自动转成额外优化任务，也不转派给其他成员。

## 4. 暂不分配，留待讨论

- 更复杂的问题与模型扩展，包括新的交互机制、供给约束、稳健优化、严格因果识别等。
- [12 个具体优化方向](./优化方向/README.md)：全部未分配负责人、未安排实施。
- [候选研究主线](./02_优化方向与研究主线.md)：保留资料，尚未选定，也不预设人员职责。
- 复杂问题的专项整合与公共组件的长期维护角色：当前不额外指定。

待三个 baseline 的结果可比较后，再共同讨论哪些问题值得深入、选什么优化方向，以及如何分工。

## 5. 交付与协作

- 各自的单问实验沿用任务卡中的独立目录；完整路线报告分别写入 `reports/Baseline-A.md`、`reports/Baseline-B.md`、`reports/Baseline-C.md`。
- 原始附件只读，不覆盖他人的代码、配置和结果。
- 共用产物以配置哈希/版本号记录；修改 Q、配比列序、Loss 口径、单位或日期后，说明受影响的下游实验。
- 公共组件可以协商复用；谁先产出不自动意味着承担长期维护或其他人的实现任务。
- 当前文档是实施分配，尚未运行模型实验。
