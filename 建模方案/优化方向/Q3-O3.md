# Q3-O3：把长上下文的预算代价解释清楚

- 建议负责人：成员乙；具体排期见[三人分工与交接](../三人分工与交接.md)。
- 状态：待 baseline 证据筛选，未启动实验。
- 本方向对应第 3 问；先阅读该问的 [baseline 索引](../baselines/README.md)。
- 研究总线、消融矩阵与交付规范：[优化方向与研究主线](../02_优化方向与研究主线.md)。

**动机。** 题设中 ℓ 是外生条件，只通过成本进入模型；这一点决定了能得出什么结论。

**研究假设。** 不同上下文要求改变同一预算能购买的训练规模，从而改变质量投入与规模投入的取舍。

**具体改进。**

- 在 C7 支持的架构情景内比较最优配置，解析解释 ℓ_crit=30000 的含义。
- 用“保持目标 Loss 所需新增算力”表示长上下文的资源代价。
- 区分上下文增大造成的训练规模损失和质量投入调整。
- 若额外研究长上下文任务收益，需要可比任务数据；作为独立扩展，不能凭空加入一个上下文奖励函数。

**验证与消融。** 固定配置只改变 ℓ，与每个 ℓ 都重新优化配置比较；展示重新分配可以补偿多少预算挤压。

**传给下一问。** 前沿预测按任务上下文需求分情景，避免把不同服务要求的模型成本混为一谈。

**降级条件。** 没有长上下文能力评测时，仅报告成本与最优训练配置影响，不宣称找到全任务最优上下文。

## 独立实施与交接

- 输入：冻结的对应问题 baseline 结果、配置、误差报告和上游接口版本。
- 实验目录：`artifacts/optimizations/Q3-O3/`；报告：`reports/optimizations/Q3-O3.md`。
- 先写一个可被否证的假设，再实施最小改动；保留同切分、同上游输入的 baseline 对照。
- 报告留出验证、消融、改进代价、不确定性和降级条件，不只展示最好看的个例。
- 若修改 Q 标度、Loss 或成本接口，列出受影响的下游任务，发布新版本后统一重算。
- 交付时明确：假设被支持、被否证或证据不足；当前方向如何衔接下一问。
